# Research: 004-external-idea-detectors

**Date**: 2026-11-22｜**狀態**：全部 NEEDS CLARIFICATION 已解（本規格無 [NEEDS CLARIFICATION] 標記，以下為設計決策與其依據）

## D1 交易日歸屬演算法（FR-003 / SC-004）

- **Decision**: 向量化規則歸屬——夜盤棒（15:00 ≤ t < 24:00 或 00:00 ≤ t < 05:00）歸屬「次一營業日」；日盤棒（08:45 ≤ t ≤ 13:44）歸屬當日。營業日＝週一~五（補班六不交易，週六日跳至次週一）。國定假日無行事曆（揭露限制，同掃描器 v3）。
- **Rationale**: 外部腳本的 `+9h` 位移在週末失準（實測：週五夜盤被歸到「週六」，TAIFEX 正解＝週一）；期交所規則（K-1 15:00 ~ K 05:00 歸 K）已於 2026-11-22 以實測 ground truth 確立。
- **Alternatives considered**: `+9h` 日曆位移（拒：週末歸屬錯誤，實測證實）；第三方假日套件（拒：引入外部依賴，假日表需人工維護，本版以揭露限制替代）。

## D2 U10 FVG 的無狀態窗口語義（FR-006）

- **Decision**: 批次 API 採「窗口內形成、窗口內判定回補」語義——窗口 W 根內形成的缺口，追蹤其後被價格回補與否；窗口前形成的缺口不回報。全歷史驗證腳本不受此限（逐根掃描全史）。
- **Rationale**: 既有範式為批量無狀態（GUI 每次重畫直呼），窗口語義與之相容且無跨呼叫狀態；全史統計由批次腳本負責，兩層各司其職。
- **Alternatives considered**: 跨呼叫有狀態快取（拒：違反既有無狀態範式，GUI 拖曳時光機會產生狀態污染）。

## D3 實證成本模型（FR-004）

- **Decision**: 來回成本區間 4.4~6.4 點，構成：手續費 30~50 元/來回（券商區間）＋期交稅 0.00002×成交價×10元/點（35000 點價位 ≈ 1.4 點/來回）。單點價值 10 元。常數命名並註來源；判定一律用區間下限（最寬鬆）與上限（最嚴格）雙值呈列。
- **Rationale**: 外部腳本 2.5 點的假設被實測否定（原始優勢 +3.6 點/筆 < 實際成本下限）；微台指乘數 10 元/點為契約規格。
- **Alternatives considered**: 固定單一成本值（拒：隱藏區間不確定性，違反誠實原則）。

## D4 時序偽象根除（FR-005 / SC-003）

- **Decision**: 事件統計以「事件根 i → 進場於 i+1 開盤、出場於固定遠景根收盤」的純前向規則，天然無同根出進；任何迴圈實作須先記錄「根初持倉狀態」再處理出場。自動化測試斷言：進場根集合 ∩ 出場根集合 = ∅。
- **Rationale**: 外部腳本實測 26~28% 進場帶同根偽象（根因：出場後立即以同根開盤價再進場）。
- **Alternatives considered**: 保留原邏輯＋事後過濾（拒：治標不治本）。

## D5 構想的量化方法（US2 / FR-007）

- **Decision**: **事件研究法（event study）**——每個偵測事件取「次根開盤進場、遠景 H 根後收盤出場」的前向報酬（點），統計筆數/勝率/平均原始點數/扣成本淨期望/累積期望曲線 maxDD；H ∈ {15, 30, 60} 三組並列。U9 作為情境切層：報告分別呈現「事件落在 killzone 內 vs 外」的對照。
- **Rationale**: 直接回答「構想本身有無優勢、優勢是否蓋得過成本」，與出場工程（SL/TP 設計）解耦；外部腳本的完整回測器把兩者混在一起且帶偽象，不可採用。
- **Alternatives considered**: 帶 SL/TP 的完整回測（拒：v1 先驗證構想純度；出場工程屬後續 spec）；僅統計訊號次數（拒：無法回答可交易性）。
