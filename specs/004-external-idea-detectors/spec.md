# Feature Specification: 外部策略構想吸收——三個 1m 偵測器（場景框架／FVG 缺口／流動性掃蕩收回）

**Feature Branch**: `004-external-idea-detectors`

**Created**: 2026-11-22

**Status**: Draft

**Input**: User description: "將兩套外部 1m 微台指策略腳本（實測證實不可交易）中的可取構想——killzone 高動能時間窗、FVG 公允價值缺口、流動性掃蕩收回（sweep & reclaim）——吸收為自家 U9/U10/U11 偵測器，以已驗證的 639,323 根真實 1m 資料鏈重測，採實際成本模型，誠實量化每個構想的原始優勢與可交易性"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 三個新偵測器獨立運作 (Priority: P1)

交易分析者在任何 1m K 線區間上，可分別呼叫三個新偵測器並取得結構化結果：

- **U9 場景框架（SessionContext）**：對每根 1m K 標註所屬交易時段（日盤/夜盤）、TAIFEX 交易日歸屬、高動能交易窗（台股開盤窗 08:45-09:30、美盤連動窗 21:30-23:30）、日盤開盤區間（08:45-09:00 前十五分鐘高低點）、以及當日結構偏見（價格相對交易日開盤與已形成區間中線的位置）。
- **U10 FVG 缺口偵測**：偵測三根 K 結構的公允價值缺口（多頭缺口＝當根低點高於兩根前高點；空頭缺口反之），缺口須大於雜訊下限（固定點數與波動度百分比取大者），回傳方向、上下緣、點數寬度。
- **U11 流動性掃蕩收回**：偵測價格掃過前 N 根高/低點流動性池後收回的行為（下影線破前低但收盤站回；上影線破前高但收盤跌回），回傳方向與觸發根。

**Why this priority**: 偵測器是本功能的價值本體；三個互相獨立，各自可單獨交付。

**Independent Test**: 對任一 1m 資料片段個別呼叫 U9/U10/U11，各自回傳結構化結果，互不依賴。

**Acceptance Scenarios**:

1. **Given** 一段含夜盤的 1m 資料，**When** 呼叫 U9，**Then** 每根 K 帶有時段標註，且週五 15:00 後與週六凌晨的 K 之交易日歸屬均為「次一營業日（週一）」，非日曆近似。
2. **Given** 三根 K 形成寬度大於雜訊下限的向上跳空結構，**When** 呼叫 U10，**Then** 標記一個多頭缺口並回傳上下緣與寬度；小於下限的雜訊缺口不標記。
3. **Given** 某根 K 低點跌破前 20 根最低點但收盤站回該最低點之上，**When** 呼叫 U11，**Then** 標記一個「掃蕩前低後收回」事件。
4. **Given** 補班週六或國定假日的無交易時段，**When** 呼叫 U9，**Then** 不生成任何 killzone 或交易日標註。

---

### User Story 2 - 全歷史誠實驗證與可交易性判定 (Priority: P2)

交易分析者對三個偵測器在完整歷史資料（639,323 根）上執行批次統計，取得每個構想的量化報告：訊號筆數、勝率、原始平均點數、**扣除實際來回成本後的淨期望**、最大回撤，以及明確的可交易性判定（可交易／不可交易／待調參）。成本模型採用實證區間（依現行費率估算 4.4~6.4 點來回），並同時列出原始未扣成本數字供對照。

**Why this priority**: 本專案鐵則「驗證通過才回報」——沒有誠實的歷史驗證，偵測器只是裝飾。此故事將外部腳本「毛利率蓋不過成本」的教訓制度化了。

**Independent Test**: 對全歷史執行批次統計腳本，產出報告檔，數字可由獨立抽樣複核。

**Acceptance Scenarios**:

1. **Given** 完整歷史資料，**When** 執行批次統計，**Then** 三個偵測器各有一份含筆數/勝率/原始點數/扣成本淨點數/maxDD 的報告，並存為檔案（CSV＋Markdown）。
2. **Given** 某偵測器原始優勢小於成本下限，**When** 報告生成，**Then** 其可交易性判定為「不可交易」且不得以任何樂觀成本假設掩飾。
3. **Given** 統計含出場與再進場，**When** 檢核資料，**Then** 不存在「同一根 K 先出場又以該根開盤價進場」的時序偽象（此為外部腳本已證實的缺陷，本功能必須根除）。

---

### User Story 3 - 終端圖表呈現 (Priority: P3)

交易分析者在桌面終端圖表（既有回放/疊圖介面）上可選擇性疊顯三個偵測器的結果：killzone 時段底色、FVG 缺口區塊（含後續被回補的狀態）、掃蕩收回標記，用於人工研判與教學複盤。

**Why this priority**: 呈現層增強可用性，但不影響核心價值（偵測＋驗證），故最後交付。

**Independent Test**: 於圖表開啟疊顯開關，三類標註正確出現在對應 K 棒上，且關閉後不影響其他圖層。

**Acceptance Scenarios**:

1. **Given** 回放至含多頭缺口的時段，**When** 開啟 U10 疊顯，**Then** 缺口區塊繪於兩根前高點與當根低點之間，且缺口被回補後呈現已回補狀態。
2. **Given** 進入 killzone 時段，**When** 開啟 U9 疊顯，**Then** 對應背景著色出現，非交易時段不著色。
3. **Given** 疊顯全開，**When** 切換畫格或拖曳時光機，**Then** 不引入可感知延遲。

---

### Edge Cases

- 資料缺口周邊（如已知的歷史斷線區段）：U10/U11 的滾動窗計算不得因缺口產生假訊號，缺口前後不得跨缺口比較。
- 交易日歸屬邊界：夜盤收尾棒（04:59）與日盤首棒（08:45）的歸屬必須與期交所規則一致；05:00-05:03 等不存在棒不得生成期望。
- 國定假日未內建行事曆：近期窗內遇假日可能高估 killzone 樣本——報告必須揭露此限制（沿用掃描器 v3 同款已知限制）。
- 結算日：標的聚合含次月契約，實測日盤交易至 13:44——U9 不需結算日特判，但報告須註明此實測依據。
- 歷史參數敏感性：killzone 時窗、流動性回看根數、FVG 雜訊下限皆可能影響結論——報告須附參數值，判定須註明「在此參數下」。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 新增三個獨立偵測器：U9 場景框架（時段/交易日/killzone/開盤區間/偏見）、U10 FVG 缺口、U11 流動性掃蕩收回。
- **FR-002**: System MUST 僅以 1m K 序列構成全部計算，禁止以非 1m 重採樣結果作為偵測依據。
- **FR-003**: System MUST 依期交所規則歸屬交易日（夜盤＝前一營業日 15:00 起至當日 05:00 前，歸屬次一營業日；週末與補班六不生成交易日），禁止使用純日曆位移近似。
- **FR-004**: System MUST 採用實證實際成本區間（4.4~6.4 點來回，可參數化）作為可交易性判定的依據，並同時呈列原始未扣成本數字。
- **FR-005**: System MUST 根除同根 K 時序偽象：任何進場與其前一趟出場不得發生於同一根 K。
- **FR-006**: System MUST 讓每個偵測器可獨立呼叫並回傳結構化結果（方向、觸發根、數值依據、理由）。
- **FR-007**: System MUST 在完整歷史資料上於 5 分鐘內完成三偵測器的批次統計。
- **FR-008**: System MUST 僅以終端輸出與檔案（CSV/Markdown）交付結果，不得建立任何網頁介面或 HTTP 服務。
- **FR-009**: System MUST 為所有偵測器常數命名並標註來源與初始依據（憲法：避免魔法數字）。
- **FR-010**: System MUST 不改動既有 U1-U8 偵測器、回放器與資料鏈的既有行為（純新增）。
- **FR-011**: System MUST 在報告中揭露已知限制（國定假日行事曆未內建、參數敏感性）。

### Key Entities *(include if feature involves data)*

- **U9 SessionContext**: 每根 1m K 的時段標註、交易日歸屬、killzone 標記、開盤區間值、當日偏見（+1/0/-1）。
- **U10 FvgDetector**: 缺口方向、上緣、下緣、寬度（點）、形成根、回補狀態。
- **U11 SweepReclaimDetector**: 掃蕩方向（掃低收回/掃高跌回）、流動性池參考值、觸發根。
- **CostModel**: 實際來回成本區間（點）、單點價值、構成說明（手續費＋期交稅＋滑價）。
- **ValidationReport**: 批次統計輸出（筆數/勝率/原始點數/淨點數/maxDD/判定/參數快照）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 三個偵測器對完整歷史 639,323 根完成批次統計，耗時低於 5 分鐘。
- **SC-002**: 產出 ValidationReport 檔案（CSV＋Markdown 各一），含筆數、勝率、原始平均點數、扣除實際成本後淨期望、最大回撤、可交易性判定。
- **SC-003**: 時序偽象檢核為 0（自動化測試驗證）。
- **SC-004**: 週五夜盤樣本抽驗，交易日歸屬 100% 為週一（自動化測試驗證）。
- **SC-005**: 既有 U1-U8 相關互動測試（15 檢查項）維持全部 PASS（回歸保護）。
- **SC-006**: 每個構想的判定包含「原始優勢 vs 實際成本」明確結論，無任何以樂觀成本掩飾的情況。

## Assumptions

- 資料源為已驗證一致的兩套 1m store（各 639,323 根，2024-07-29 ~ 2026-11-21）。
- 外部腳本僅作為構想來源；其程式碼不直接採用（其回測器存在已證實的時序偽象與樂觀成本缺陷）。
- 構想初始參數沿用外部腳本（killzone 窗 08:45-09:30 與 21:30-23:30、流動性回看 20 根、FVG 雜訊下限 3 點或 0.25 倍波動度取大），計畫階段可調整並須留紀錄。
- 單點價值 10 元（微型台指契約乘數）、最小跳動 1 點（實測資料為整數點）。
- 國定假日行事曆未內建為已知限制（未來另案整合期交所行事曆）。
